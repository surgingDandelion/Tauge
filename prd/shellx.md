## 1. 背景与目标

### 1.1 背景
Xshell 长期只提供 Windows 版本，macOS 用户通常只能组合使用 iTerm2（没有主机管理功能）+ 命令行 scp/rsync + Finder，或者接受 Termius / SecureCRT 的订阅制、高价或云端账号体系。运维与开发人员在 macOS 上的高频痛点集中在四件事：

1. 主机多、环境多（生产/预发/测试），没有分组与快速检索，靠记忆 IP；
2. 内网机器必须经过跳板机或公司 HTTP 代理，命令行拼 `ProxyJump` 容易出错、排障困难；
3. 改一个配置文件要“开终端 → cd → vim”或在多个工具间切换；
4. 上传下载靠 `scp` 命令，路径长、无进度、无断点。

### 1.2 产品目标
做一个 **本地优先（local-first）、原生体验、终端 + 文件传输一体化** 的 macOS SSH 客户端。

| 目标 | 可量化指标 |
|---|---|
| 连接效率 | 任意已保存主机 ≤ 3 次点击 / 1 次 Cmd+K 搜索即可连上 |
| 不离开应用完成日常运维 | 目标场景中 ≥ 90% 的操作（连机器、看日志、改配置、传文件）无需切换其他 App |
| 文件操作成本 | Finder 拖入即上传，≤ 2 步完成；上传有进度、可取消、可续传 |
| 复杂网络可达 | 支持 HTTP 代理 + 多级跳板任意组合，失败可定位到具体环节 |

### 1.3 非目标（首版明确不做）
- 不做 X11 转发 / 图形化远程桌面；
- 不做团队协作、云端同步、Web 端（V2 再评估）；
- 不做 Windows / Linux 客户端（架构上预留，不作为首版交付）；
- 不做内置 SQL 客户端、服务器监控面板等“运维平台化”功能。

## 2. 目标用户与典型场景

| 角色 | 特征 | 核心诉求 |
|---|---|---|
| 后端/运维工程师 | 管理 20~200 台主机，多环境 | 分组、跳板机、批量命令、日志查看 |
| 独立开发者 / 小团队 | 1~5 台 VPS，用密钥登录 | 上手快、免费或低价、拖拽传文件 |
| 数据/算法工程师 | 连 GPU 机器跑任务 | 长会话稳定、断线重连、大文件传输 |

**关键场景**

- S1 生产排障：公司网络 → HTTP 代理 → 堡垒机 A → 内网机 B，一条链路打开终端。
- S2 改配置：终端里定位到 `/etc/nginx/conf.d/`，直接在同一窗口侧栏打开 SFTP 编辑并保存。
- S3 传包：把本地 `build/app.tar.gz` 从 Finder 拖到终端窗口，自动上传到当前目录并回填路径。
- S4 多机对比：同时开 4 个标签，广播输入执行同一条命令（P1）。
- S5 弱网/高延迟：连接 300ms RTT 的海外机器，输入不卡顿，断线后一键重连并提示 tmux。

## 3. 术语

| 术语 | 说明 |
|---|---|
| 跳板机 / Jump Host | 通过 SSH 的 `direct-tcpip` 通道转发到下一跳，逐跳建立 SSH 连接（等价 OpenSSH `ProxyJump`） |
| 代理 | 出站 TCP 代理，HTTP CONNECT 或 SOCKS5，仅用于建立到第一跳的 TCP 连接 |
| 会话（Session） | 一个标签页内的一个 SSH shell 通道 |
| 连接（Connection） | 一条 TCP+SSH 传输层连接，可承载多个会话通道与一个 SFTP 子系统 |
| TOFU | Trust On First Use，首次连接记录主机公钥指纹 |

## 5. 信息架构与界面

**主窗口：三栏 + 标签工作区**

```
┌───────────────┬──────────────────────────────────────────────┐
│ 侧边栏 (240pt)│  标签栏： [prod-web-01] [预发-db] [+]         │
│ 搜索框        ├──────────────────────────────────────────────┤
│ ▾ 生产环境    │                                              │
│   • web-01    │   终端区（xterm 兼容渲染）                    │
│   • db-01     │   ┌──────────────────────────────┐           │
│ ▾ 测试环境    │   │ 或 SFTP 双栏（本地 / 远端）  │           │
│ ▸ 我的 VPS    │   └──────────────────────────────┘           │
│               ├──────────────────────────────────────────────┤
│ [+ 新建主机]  │ 状态栏：已连接 · 32ms · aes256-gcm · 代理:公司 │
└───────────────┴──────────────────────────────────────────────┘
```

- 侧边栏：分组树 + 收藏 + 最近连接；支持拖拽移动分组、右键菜单、多选批量操作。
- 终端与 SFTP 关系：**同一标签内可切换 / 右侧抽屉并排显示**，共享同一 SSH 连接与同一当前目录（关键体验点）。
- 全局命令面板 `Cmd+K`：搜索主机、执行“新建标签/打开 SFTP/切换主题”。
- 首次启动：空状态引导“新建主机 / 从 ~/.ssh/config 导入”。

## 6. 功能需求

> 优先级：P0 = MVP 必须；P1 = V1；P2 = 后续。每条含验收要点。

### FR-1 主机与分组管理（P0）

**主机字段**

| 字段 | 说明 |
|---|---|
| 名称 / 备注 / 标签 / 颜色 | 名称可重名，展示用；标签用于筛选 |
| 地址 / 端口 / 用户名 | 端口默认 22；支持 IPv6、域名 |
| 认证方式 | 密码 / 私钥 / SSH Agent / 键盘交互 |
| 私钥 + passphrase | passphrase 可选择保存到钥匙串 |
| 代理 | 继承分组 / 无 / 指定代理 |
| 跳板链 | 继承分组 / 直连 / 选择主机（可多级） |
| 终端 | 类型（xterm-256color）、编码（UTF-8/GBK）、初始目录、启动命令 |
| 连接参数 | 保活间隔、超时、连接复用开关 |

**分组能力**
- 无限层级树；分组本身可作为“默认值模板”（代理、跳板、编码、字符集、日志开关向下继承，主机级覆盖）。
- 拖拽移动、重命名、删除（子项需二次确认）、组内排序、组折叠状态持久化。
- 分组右键：在此组新建主机、批量连接（每台开一个标签 / 一个分屏）。

**检索与入口**
- 搜索匹配：名称、地址、用户名、标签、备注，支持拼音首字母与模糊匹配。
- 收藏、最近连接（按时间倒序，最多 20）、菜单栏常驻图标（P1）。

**导入导出（P1）**
- 导入 OpenSSH `~/.ssh/config`：`Host / HostName / User / Port / IdentityFile / ProxyJump / ProxyCommand(nc 形式)`，`Host *` 通配作为默认值。
- 导入 CSV/JSON（自定义模板）；导出支持“含/不含凭据”，含凭据时必须设置导出密码。
- 不承诺解析 Xshell 加密会话文件（格式私有），可作为待确认项。

**验收**：新建分组“生产/华东”并把 3 台主机拖入，退出重启后结构、顺序、折叠状态完全一致；搜索“sh”能命中 shenzhen-db-01。

### FR-2 认证与密钥（P0）

- **密码**：保存到 macOS Keychain（`kSecAttrAccessibleAfterFirstUnlock`），可选择“每次询问”；密码永不出现在日志与崩溃报告中。
- **私钥**：支持 OpenSSH 新格式、PEM/PKCS#8；算法 Ed25519 / ECDSA / RSA；自动检测加密私钥并请求 passphrase；支持“从文件导入”和“从 ~/.ssh 目录选择”。
- **SSH Agent**：使用 `SSH_AUTH_SOCK` 中的身份（P1），并可选择是否启用 Agent 转发。
- **键盘交互（keyboard-interactive）**：支持多轮 challenge（OTP / MFA），提示文本原样展示，支持“记住本轮答案 30 秒”。
- **密钥生成器（P1）**：默认 Ed25519，可生成 RSA 4096；展示公钥、复制、可一键追加到目标机 `~/.ssh/authorized_keys`。
- **主机密钥校验**：首次连接以 TOFU 展示 SHA256 指纹（可选 MD5），用户确认后写入 known_hosts；指纹变化时**阻断连接**并高亮告警，提供“查看新旧指纹 / 删除记录”操作；支持导入导出 known_hosts、按主机重置。
- **错误可诊断**：区分 DNS 失败、TCP 拒绝/超时、代理握手失败、算法协商失败、认证被拒、权限不足，并给出建议（如“服务器仅支持 ssh-rsa，建议改用 rsa-sha2-256”）。

**验收**：使用带 passphrase 的 Ed25519 私钥 + OTP 完成登录；篡改 known_hosts 后连接必须被阻断且提示明确。

---

### FR-3 终端（P0）

- **多标签**：`Cmd+T` 新建、`Cmd+W` 关闭（有活动进程时确认）、`Cmd+1..9` 切换、拖拽重排、拖出成为独立窗口（P1）。
- **分屏**（P1）：水平/垂直分割，同一连接或不同连接混排。
- **渲染兼容**：xterm-256color、24-bit 真彩、UTF-8 与 GBK 切换、CJK 宽字符对齐、制表符与零宽字符、鼠标上报（vim/tmux/htop）、括号粘贴、OSC 8 超链接、OSC 52 剪贴板（需授权确认）。
- **滚动与搜索**：滚轮回滚、`Cmd+F` 增量搜索并高亮、回滚缓冲默认 10,000 行（可配至 100,000），超限时内存受控。
- **复制粘贴**：选中即复制（可关）、`Cmd+V` 粘贴；多行粘贴时弹确认（防误执行，可关）；粘贴内容不自动执行。
- **键盘**：`Option` 作为 Meta 可配置；自定义键位映射（如 `Cmd+←` → `Ctrl+A`）；常用快捷键表见附录。
- **字体与外观**：等宽字体族/字号/行高/字距、光标样式与闪烁、主题（内置 6 套 + 导入 iTerm 颜色方案）、背景透明度与模糊。
- **会话生命周期**：断开时保留内容并显示原因 + `重新连接`；可选自动重连（指数退避）；重连后提示“检测到 tmux 会话，是否 attach”。
- **会话日志**（P1）：可全局或按主机开启，路径模板 `~/Logs/{host}/{date}.log`，支持脱敏规则（正则替换密码/token）。
- **状态栏信息**：连接状态、RTT、加密/密钥交换/MAC 算法、是否经代理、跳板链（`→ prod-bastion → 10.0.3.4`）。

**验收**：`vim` 全屏编辑、`tmux` 分屏、`htop` 颜色与鼠标均正常；中文与 emoji 不错位；1 万行输出不卡顿。

### FR-4 SFTP 文件管理（P0）

**浏览**
- 双栏（本地 / 远端）或单栏 + 侧栏；面包屑 + 地址栏输入跳转；前进/后退/上级/刷新；显示隐藏文件开关。
- 列表字段：名称、大小、权限（`rwxr-xr-x` 与 755 双显）、属主/属组、修改时间；排序；`Cmd+↑/↓` 键盘导航。
- 目录懒加载 + 虚拟滚动，万级文件目录不阻塞 UI；显示/隐藏点文件；符号链接标记与“跟随/不跟随”策略。
- 双击：小文件（< 2MB，可配）用内置编辑器打开；大文件提示“下载后编辑”。

**操作**
- 新建文件夹/空文件、重命名（F2）、删除（文件直接确认，目录二次确认并提示递归）、复制路径、计算目录大小（P1，异步）、chmod（数字/符号）、修改时间（P2）。
- 内置编辑器（P1）：语法高亮、编码/BOM/换行符保留、保存前检测远端 mtime 变化并提示冲突、保存失败可另存。

**传输**
- 上传 / 下载 / 目录递归；多选与文件夹整体拖入。
- 进度：总进度 + 单文件进度、速度、剩余时间；支持**暂停/继续/取消**、失败重试（可配 3 次）、失败列表可“重试全部”。
- **断点续传**：基于 SFTP `READ/WRITE` 的 offset 续写，重连后可按文件大小/mtime 判断续传点。
- 并发队列：默认 2 个并发文件，可配 1–4；单文件分块写入需遵循通道最大报文限制（规范下限 32KB，见 §10）。
- 冲突策略：覆盖 / 跳过 / 重命名（`file (1).txt`）/ 仅较新者，可“应用于全部”。
- 传输中心（P1）：统一查看历史与进行中任务，可全部暂停。

**拖拽（核心差异化）**
| 拖拽路径 | 行为 |
|---|---|
| Finder → 远端文件面板 | 上传到当前远端目录，拖入时高亮目标目录 |
| Finder → 终端区域 | 上传到该会话当前工作目录（通过 `pwd` 探测或最近 `cd` 推断），完成后在光标处插入远端路径 |
| Finder → 侧边栏主机 | 上传到该主机配置的“默认上传目录” |
| 远端文件 → Finder / 桌面 | 下载（使用 file promise，避免先落临时文件） |
| 远端 ↔ 本地面板 | 上传 / 下载入队 |

**验收**：拖一个 500MB 文件与一个含 200 文件的目录，进度准确、可暂停继续、断网重连后可续传；拖到终端后路径正确回填且未自动回车执行。

### FR-5 跳板机 / ProxyJump（P0）

- 配置入口：主机编辑页“跳板机”下拉，**从现有主机列表选择**（复用其地址、端口、用户名、认证、代理），支持 1–3 级链路。
- 链路可视化：`本地 →(代理)→ 跳板A → 跳板B → 目标`，每跳显示状态灯与耗时。
- 每一跳独立认证：跳板机使用自己的凭据；支持“与目标机相同凭据”快捷勾选。
- 失败定位：明确提示“第 2 跳 10.0.3.4:22 认证失败”，而不是笼统“连接失败”。
- **连接复用**：同一跳板的多条会话复用一条到跳板的 SSH 连接（多路复用），并缓存 `direct-tcpip` 通道；跳板断开时提示影响的所有标签（P1）。
- 兼容导入：`~/.ssh/config` 的 `ProxyJump a,b` 与简单 `ProxyCommand ssh -W %h:%p jump`（P1）。
- 边界：跳板机必须支持 `direct-tcpip` 转发（默认开启）；若不支持，提示改用“本地端口转发”方式（P1）。

**验收**：配置 A（HTTP 代理可达）→ B（密码）→ C（私钥）三跳链路成功打开终端与 SFTP；断开 B 后给出准确提示。

### FR-6 网络代理（P0）

- 类型：无 / **HTTP CONNECT** / SOCKS5 / SOCKS5h（远端 DNS）/ HTTPS 代理（P2）。
- 参数：主机、端口、用户名、密码（Keychain 保存）、是否对代理服务器做 TLS 校验（P2）。
- 认证：HTTP Basic（`Proxy-Authorization`）；SOCKS5 用户名/密码（RFC 1929）。
- 作用域与优先级：**主机级 > 分组级 > 全局默认**，UI 明确显示“当前生效：分组‘生产’的代理”。
- 连通性测试：填写后可“测试”，输出 DNS/连接/代理握手/认证各阶段耗时与错误码。
- 与跳板组合：代理仅用于建立到**第一跳**的 TCP 连接，后续跳通过 SSH 通道转发，不重复走代理。
- 说明：不支持 PAC 脚本、不支持系统代理自动继承（P2 可读系统配置）。

**验收**：在只能经 HTTP 代理出网的环境下，通过带认证的代理连接成功；代理密码错误时错误信息可区分“407 认证失败”。

---

### FR-7 设置与其他（P0/P1）

- 设置分组：通用、外观、终端、传输、安全、快捷键、高级、关于。
- 崩溃/退出恢复：重启后恢复标签列表与各标签最后目录（不恢复会话内容与密码）。
- 更新：Developer ID 版用 Sparkle 增量更新；含 Beta 通道开关。
- 多语言：简体中文、英文；深浅色跟随系统 + 手动覆盖。
- 隐私：不上传任何主机信息；可一键导出/清除本地数据。

## 7. 关键流程

### 7.1 连接建立状态机

```
[点击连接]
  → 解析代理（主机/分组/全局）
  → (有代理) TCP → CONNECT host:port → 200 才继续；407/超时 → 失败(代理)
  → (无代理) TCP 直连
  → SSH 传输层握手（KEX / 主机密钥）
  → known_hosts 校验：未知→TOFU 弹窗；变更→阻断
  → 用户认证（密码/公钥/键盘交互，可多轮）
  → (有跳板) 打开 direct-tcpip 通道 → 在通道上重复 传输层握手+认证（每跳一次）
  → 目标机认证通过
  → 打开 session 通道 → PTY 请求(尺寸) → shell
  → 打开 sftp 子系统通道（与 shell 同连接，懒加载）
  → 状态栏就绪
```
任一步失败：保留错误阶段标签，提供“重试 / 编辑此主机 / 查看诊断日志”。

### 7.2 拖拽上传时序

```
dragEntered → 校验 pasteboard 含 public.file-url → 高亮目标
drop → 读取 URL 列表（去重、展开目录、跳过不可读）
     → 计算总大小 → 若目标已存在同名 → 冲突对话框
     → 入队（并发上限）→ 分块 write（≤ peerMaxMessageSize）
     → 更新进度 → 单文件完成校验（大小 / 可选 mtime）
     → 全部完成 → 刷新目录 → 若拖到终端则插入路径文本
```

## 8. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 冷启动 ≤ 1.5s；终端按键到本地回显 ≤ 16ms（不含网络）；输入 60fps 不丢帧；万级目录首屏 ≤ 2s；SFTP 单文件吞吐 ≥ 50MB/s（千兆内网）；RTT 300ms 下可正常交互 |
| 资源 | 空载内存 ≤ 200MB；10 个活动标签 ≤ 700MB；空闲 CPU ≈ 0%；无传输时磁盘 IO 为 0 |
| 稳定 | 连续 8 小时会话不中断、无内存增长（回滚缓冲有上限）；崩溃率 < 0.1% 会话；异常退出后可恢复标签 |
| 安全 | 仅启用现代算法（禁用 ssh-rsa/SHA1、CBC、3DES）；凭据仅存 Keychain，配置文件中仅存引用；日志默认脱敏；敏感内存用后清零；导出含凭据必须加密 |
| 兼容 | macOS 13 / 14 / 15+；Apple Silicon 与 Intel；OpenSSH 7.4–10.x 服务端；Ubuntu/CentOS/RHEL/Debian/Alpine/macOS 远端；非 POSIX shell 不支持（明示） |
| 可用性 | 所有危险操作可撤销或二次确认；错误信息必须包含“发生了什么 + 可能原因 + 建议动作” |
| 合规 | 不含 GPL 代码（若用 libssh2 需注意 BSD 许可可用；SwiftTerm 为 MIT）；App 内不含遥测默认开启项 |

## 9. 数据模型（本地 SQLite 草案）

```sql
groups(id, parent_id, name, sort, defaults_json)              -- 层级 + 继承默认值
hosts(id, group_id, name, hostname, port, username, auth_type,
      key_id, proxy_id, jump_host_id, term_type, encoding,
      start_dir, keepalive, reuse_conn, tags, color, notes,
      created_at, updated_at, last_used_at, use_count)
credentials(id, kind, ref)        -- kind: keychain 引用 / agent / prompt
private_keys(id, name, public_key, fingerprint, storage_ref)   -- 私钥本体在 Keychain 或加密 blob
proxies(id, type, host, port, username, auth_ref)
host_keys(host_port, key_type, fingerprint, first_seen)        -- known_hosts
session_logs(id, host_id, path, started_at, size)
snippets(id, name, command, tags)                              -- 命令片段（P1）
transfers(id, host_id, direction, src, dst, size, state, bytes_done, updated_at)
settings(key, value)
```

**凭据加密方案**：随机生成 256-bit 主密钥存 Keychain；数据库内的密码/passphrase 用 AES-256-GCM 加密，附 host id 作为 AAD，防止跨记录复用。

## 10. 技术方案建议

### 10.1 三条路线对比

| 方案 | 技术栈 | 优势 | 风险 |
|---|---|---|---|
| **A. 原生 Swift（推荐）** | SwiftUI + AppKit + SwiftTerm + SwiftNIO SSH | 启动快、内存低、终端/拖拽原生手感、公证与签名链路简单 | SFTP 需自行实现或依赖第三方；SwiftNIO SSH 官方定位是“协议构建块”而非成品客户端 [cite:01a7101e-1] |
| B. Electron | xterm.js + ssh2 + node-pty | SSH/SFTP/代理/跳板生态成熟（ssh2 直接支持 SFTP、ProxyJump、SOCKS），开发快 [cite:734673b6-2] | 体积 100MB+、内存高、终端与拖拽的原生感弱、能耗与公证成本 |
| C. 混合 | Rust（russh）+ SwiftUI 前端 | 性能与跨平台潜力好 | FFI 维护成本高、团队要求高 |

**推荐：方案 A（原生）**，理由是终端与文件拖拽的手感是本产品核心差异点；已有同类产品验证该栈可行：SwiftTerm 提供终端仿真与渲染、SwiftNIO 提供 SSH，二者组合可做出原生 macOS SSH/SFTP 客户端 [cite:01a7101e-5][cite:01a7101e-2]。

### 10.2 关键技术点与预研项

1. **SFTP 客户端**：SwiftNIO SSH 本身不提供 SFTP，需实现 SFTP v3 子集（realpath/stat/list/open/read/write/rename/mkdir/rmdir/remove/setstat），并处理 `posix-rename@openssh.com` 等扩展；社区已有基于 SwiftNIO SSH 的 SFTPClient 实现可评估复用 [cite:8667fb16-1]。**这是 MVP 最大技术风险，需 M0 阶段做 PoC。**
2. **分块与背压**：SFTP 写包必须按子通道最大报文大小切分，规范下限 32768 字节，超限会导致部分服务端“卡死等待数据” [cite:8667fb16-4]。实现上取 `max(32768, peerMaxMessageSize)` 并做并发窗口（如 8–16 个 in-flight 请求）以提升吞吐。
3. **跳板机**：用 `direct-tcpip` 子通道承载下一跳的 SSH 流量，逐跳嵌套；需自行管理每跳的认证与 host key。
4. **HTTP 代理**：自行实现 `CONNECT` 握手 + Basic 认证，SOCKS5 需实现 RFC 1928/1929。
5. **拖拽**：`NSView.registerForDraggedTypes([.fileURL])` + `NSDraggingDestination`（`draggingEntered` / `performDragOperation`），从 Finder 拖入的文件以 `public.file-url` 提供 [cite:c7bf746a-2]；向外拖出用 `NSFilePromiseProvider` 实现“边下边到磁盘”。
6. **终端引擎**：优先 SwiftTerm（MIT，支持 OSC 1337/kitty 剪贴板等较新特性）[cite:01a7101e-3]；需自测 CJK 宽度与 tmux 兼容性。
7. **分发与沙盒**：建议 Developer ID 签名 + 公证 DMG 直发；App Store 沙盒下 `~/.ssh` 与任意路径访问受用户授权限制，可作为后续评估项。

## 13. 验收清单（MVP 出口条件）

1. 新建分组“生产/测试”，各建 2 台主机，重启后结构与排序保持。
2. 密码登录、Ed25519 私钥（带 passphrase）登录、私钥 + OTP 登录均成功。
3. known_hosts 指纹变更时连接被阻断且提示新旧指纹。
4. 打开 5 个标签，`vim`、`tmux`、`htop`、`top` 显示正常，中文与 emoji 对齐正确。
5. 通过带认证的 HTTP 代理连接成功；代理错误可区分认证失败与网络不可达。
6. 配置 A→B 两级跳板，终端与 SFTP 均可用；断开 B 时提示准确。
7. 从 Finder 拖入 500MB 文件与 200 文件目录，进度/暂停/续传/冲突策略全部正常。
8. 拖文件到终端区域，上传完成后路径正确插入且不自动执行。
9. 拖远端文件到桌面，文件完整下载（大文件无内存暴涨）。
10. 8 小时挂机会话不断，内存无持续增长；强制退出后重启可恢复标签。

## 14. 待确认问题

1. 是否需要在 MVP 就支持 **SOCKS5**（部分公司只给 SOCKS），还是 V1？
2. 跳板机是否要求支持**从跳板机反向访问本地**（远程端口转发）？影响代理与端口转发优先级。
3. 是否需要**命令片段库 / 批量执行**（这会让产品靠近运维工具，影响范围与排期）。
4. 商业模式：买断、订阅、免费 + Pro（决定是否要做账号/授权服务与更新通道）。
5. 是否需要 App Store 上架（决定沙盒适配工作量，可能影响 `~/.ssh` 直接读取体验）。
6. 团队技术栈偏好：若成员以 Web 为主，建议改走 Electron，MVP 可缩短约 3–4 周，但需接受体积与内存指标放宽。
